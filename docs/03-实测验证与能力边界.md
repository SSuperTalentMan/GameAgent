## 一、验证环境（够不够跑，是这套方案的第一道门槛）

| 项 | 实际配置 |
|---|---|
| 设备 | 笔记本（LAPTOP-J24LPBEK），Intel Core 5 220H，16 GB 内存，集显 128 MB，无独显 |
| 系统 | Windows 11 64 位，Python 3.12（uv 虚拟环境） |
| 大模型 | 阿里云百炼 `qwen3.8-flash`（OpenAI 兼容接口，`API_KEY` 走环境变量） |
| 本地模型 | `bert-base-chinese`（意图识别）、`bge-m3`（向量化）、`bge-reranker-v2-m3`（重排序，CPU 推理） |
| 存储 | MySQL 8（`asyncmy`）、Redis（`asyncio`）、Neo4j（bolt）、Milvus Lite 3.x（Windows 原生） |
| 运行时栈实测 | `{"db": "mysql", "kv": "redis", "graph": "neo4j", "vector": "milvus-lite", "llm": "qwen3.8-flash"}` |

**这台机器能跑通全部 9 个服务 + 4 个存储 + 本地模型推理**，是这个 Demo 的硬约束之一：方案不能只在 GPU 服务器上成立。

## 二、自动化测试：22 条，重点在"防自欺"

```bash
.venv/Scripts/python.exe -m unittest discover -s tests
# Ran 22 tests ... OK
```

测试不是为了覆盖率，是为了锁住**曾经骗过自己**的地方：

| 测试文件 | 锁住的行为 |
|---|---|
| `tests/test_contracts.py` | 断言类型判定；`window.game.start()` 不能被当成胜利断言；"在 playing 状态下…分数从 0 变为 1"不能被降级成"画布存在即通过"；"金币"单独出现不算计分；规格 ID 重复/依赖不存在的机制必须被拒 |
| `tests/test_template_and_artifacts.py` | 降级模板的 XSS 转义；模板必须通过 JS 语法检查；生成代码里的 JS 语法错误（重复声明）必须被拦；缺 `canvas` / `__game` 必须报问题 |
| `tests/test_qa_runtime.py` | **反例**：状态是 `win` 但胜利文案被 CSS 隐藏时，QA 必须判失败 |
| `tests/test_state_and_metrics.py` | 状态写入保留 meta 并同步缓存；`error` 会话不丢；`quit` 会话计入流失；回访率只由"真的产生了第 2 个会话的玩家"决定 |
| `tests/test_intent_rules.py` | 规则信号的"单意图精确命中"：查询句不命中 fix；需求句里出现"会失败"时保持歧义、交给 BERT |

## 三、端到端实跑记录

### 3.1 一次"一次通过"的运行（交付验收跑，`docs/logs/final_run.log`）

| 阶段 | 实测结果 |
|---|---|
| 意图识别 | BERT（本地 `bert-base-chinese`）判定 `new_requirement`，非规则兜底 |
| 规格 | 6 条可执行断言落库，9 个机制节点与依赖写入 Neo4j |
| RAG 参考 | 召回 3 条（胜负条件设计 / 竞速 vs 收集 / 碰撞与漏接判定），`bge-m3` 召回 + `bge-reranker-v2-m3` 精排 |
| 编码 ∥ 资产 | `game.html`（LLM 生成，非模板）；资产 `player.png` / `coin.png` / `player.glb`（程序化占位，文生图关闭） |
| QA | **6/6 断言通过，0 轮修复**；逐条证据见下表 |
| 静态审查 | `pass`，0 findings |
| 玩家模拟 | 8 玩家 × ≤2 会话 → **14 个会话 / 135 条行为事件**（win 11 / lose 3；6 人真正产生了第 2 会话，回访率 75%） |
| 市场验证 | 完成率 79%、回访率 75%（非真实留存）、模拟付费事件率 7.1%，报告落库 |
| 交付 | H5 部署 URL 就绪；APK 为 `bundle_ready`（本次跳过真实构建） |
| 任务状态 | `completed_with_warnings`（MVP 就绪，安装包未构建，两者分开表达） |

**QA 逐条证据（真实日志，不是构造）**：

| 断言 | 类型 | 证据 |
|---|---|---|
| A1 启动 | `start` | `canvas存在=True, 开始后 status=playing` |
| A2 计分 | `score` | `核心动作一次后分数 0 → 1` |
| A3 胜利 | `win` | `9 次动作后 status=win, score=10, 规格阈值=10` |
| A4 失败 | `lose` | `3 次 core fail 后 status=lose, DOM可见=True, 文案='游戏结束，漏接太多！'` |
| A5 移动 | `controls` | `playerX: 208 → 左键 184 → 右键×2 232`（真实键盘事件） |
| A6 胜利文案 | `win_text` | `status=win, DOM可见=True, 文案='恭喜！你赢了！'` |

这些证据现场可复现：截图 `qa_win_v1.png` / `qa_lose_v1.png`、逐条 JSON 都在 `generated/{task_id}/` 下。

**复跑确认**（`docs/logs/repeat_run.log`，改完配置化之后重跑一遍）：同一句需求、6 条断言同样全通过、0 轮修复，静态审查 `pass`；玩家侧 8 玩家 × 2 会话 → 14 会话 / **149 条事件**（win 8 / lose 6，完成率 57%）。两次跑出的断言结论一致、行为分布有差异（149 vs 135 条），说明玩家行为不是写死的——这正好也验证了"合成数据只能看趋势，不能当结论".

**顺带一个成本观察**：同一 prompt 第二次运行时命中了 Redis 里的 LLM 缓存，编码阶段从数分钟降到 22 秒——这也是把缓存做进 LLM 网关（而不是各 Agent 各自缓存）的直接收益。

### 3.2 一次"QA 抓到真 bug、修复轮救回来"的运行

这一轮更能说明门禁有用，因为它不是顺风顺水：

| 时间 | 事件 |
|---|---|
| — | 规格 7 条断言 |
| — | Engineer 生成 v1，静态检查（有没有 `canvas`/`__game`）全部通过 |
| — | **QA 判 0/7 全失败**，证据：`Identifier 'miss' has already been declared` —— LLM 写出了重复声明的 JS，页面加载即抛异常 |
| — | 编排器按所有权表回退：受影响机制 `['M2','M3','M4','M6','M7','M8','M9']`，路由给 `engineer_agent`，携带 v1 完整代码与失败证据 |
| — | Engineer 产出 v2 |
| — | **QA 7/7 通过（1 轮修复）**，静态审查 pass |
| — | 玩家模拟 127 条事件；市场验证报告落库；H5 部署 URL 就绪 |

**这轮暴露的工程问题**：静态文本检查看不出 JS 语法错误，只能靠 QA 兜底，一失败就烧掉一整轮修复预算（数分钟 LLM 调用）。已补：`engineer_agent` 在写盘前用 Node `--check` 做语法校验，不合格直接带错误信息重试一次（`app/agents/engineer.py::check_js_syntax`），并有单测覆盖。

### 3.3 运行耗时（本机，非 GPU）

| 阶段 | 耗时量级 |
|---|---|
| 服务启动 + 四个存储连接 + 本地模型加载 | 25~40 s |
| 规格生成（含 RAG 召回与重排） | 25~35 s |

## 四、实测暴露并修复的问题（面试最值得讲的部分）

| # | 问题 | 现象 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | QA 假通过 | 状态是 `win`，但胜利文案被 CSS 隐藏，玩家看不到，QA 仍判通过 | 判据只有 `state === 'win'` | 三重判定：状态 + DOM 可见 + 文案与规格一致；补反例单测 |
| 2 | A2A 根路由 404 | 9 个服务健康检查全绿，但编排器调用下游 `POST /` 返回 404 | 系统代理劫持了 `127.0.0.1` 请求，`httpx` 默认 `trust_env=True`，请求以 absolute-form 发出 | 内部调用统一 `trust_env=False`；健康检查不能替代真实调用验证 |
| 3 | BERT 静默降级 | 日志里意图识别一直走规则，BERT 从未生效 | 模型目录多套一层 `bert-base-chinese/bert-base-chinese/`，tokenizer 加载失败被吞 | 配置里做候选路径探测；降级写日志并进健康检查，不再静默 |
| 4 | 断言被降级 | "接金币后分数从 0 变为 1"实际只验证了"画布存在" | 断言分类里"start"分支先命中，因为句子里有"在 playing 状态下" | 调整判定顺序（start 最后判），计分只认显式计分词；补回归测试 |
| 5 | 留存恒为 100% | 指标报告显示"重复会话率 100%" | 模拟器写死每个玩家跑 2 个会话，"留存"测的是配置不是行为 | 回访改为按玩家画像概率决定；补"回访率只由真实产生的第 2 会话决定"单测 |
| 6 | 玩家行为同质 | 12 个会话全部 `win`，没有失败、没有流失 | 所有玩家共用一套策略参数 | 引入 4 类玩家画像（休闲/急性子/熟练/探索）轮转分配，中途放弃独立成 `quit` 状态 |
| 7 | 报告撰写拖垮整条流水线 | 代理 502 导致 `market_agent` 失败，任务被判 `failed` | 分析链失败被当成质量门禁失败；LLM 底层异常没收敛成 `LLMError` | 异常收敛 + 分析链/交付链降级不阻塞；只有 QA + 静态审查失败才判 `failed` |
| 8 | 静态审查不阻塞 | 引用了不存在的资产也能交付 | 早期审查只记录不阻断 | error 级 findings 阻塞交付并触发资产重建 |
| 9 | 意图识别误判 | "查询任务 task-xxx 的状态"被判成 `fix`（置信度 0.757），返回的是"无需修复"而不是任务状态 | BERT 锚点句向量法对"任务/状态"这类两批锚点共有的词不敏感，纯语义相似度分不开 | 改成"高精度规则优先、BERT 处理歧义"：只命中单一意图关键词时采信规则，多意图命中才交给 BERT；冲突时打日志可观测 |

## 五、能力边界（主动交代，不等被问）

| 能力 | 现在到哪一步 | 为什么没继续做 | 要补什么 |
|---|---|---|---|
| 游戏品类 | Canvas 单页小游戏（接金币类核心循环） | 目标是验证流水线与门禁，不是做引擎 | 接 Phaser/Pixi 模板与资源管线，按品类扩模板库 |
| 3D 资产 | 接口预留 + 程序化占位 GLB | 本机集显 128 MB，本地跑不动 3D 生成 | 接外部文生 3D 服务（Tripo / Hunyuan3D 等） |
| 文生图 | 万相接口已接，可按开关关闭 | 额度与成本控制，演示时默认走程序化占位 | 额度管理与缓存复用 |
| APK | Capacitor + Gradle 真实构建，已产出 3.6 MB debug 包（`generated/task-28b325fd/build/task-28b325fd-debug.apk`） | 单次构建数分钟，流水线里默认关闭（`ANDROID_SDK_ROOT` 置空即跳过） | 迁到 CI/云构建机，加签名与版本号管理 |
| iOS | 仅接口预留 | 需 macOS + Xcode | 云打包（Bitrise / Codemagic） |
| AI 玩家规模 | 实测 8~10 玩家并发（8 玩家 × 2 会话 = 14 会话 / 135 事件）；16 为配置上限、未压测 | 单进程 Playwright 的 CPU/内存上限 | 远程浏览器池 + 事件走队列/时序库 |
| 玩家决策质量 | 规则策略 + 关键点 LLM 介入（有预算护栏） | LLM 逐帧决策成本不可接受 | 行为克隆（用真实玩家日志训决策模型） |
| 市场结论 | 合成行为指标，显式标注"非真人" | 没有线上投放与埋点数据 | 接埋点/归因，用真实数据校准口径 |
| 生成代码安全 | 子进程隔离执行、禁止外链、内容大小上限、路径穿越校验 | 还没有容器级沙箱 | Docker/gVisor 级隔离，网络 egress 白名单 |
| 并发任务 | 单任务串行，状态机不支持并发抢占 | Demo 场景是单人单任务 | 任务队列 + 租约 + 幂等键 |

## 六、怎么复现（给面试官的三条命令）

```bash
# 1. 依赖（uv 管理）
uv pip install -r requirements.txt -p .venv
.venv/Scripts/python.exe -m playwright install chromium

# 2. 环境变量（密钥只走环境变量，不落库不进代码）
#    API_KEY=<百炼 key>；MySQL/Redis/Neo4j 连接串见 .env.example

# 3. 跑全链路（跳过 APK 构建）
ANDROID_SDK_ROOT= .venv/Scripts/python.exe -m app.runner --no-wait

# 可选：起前端控制台
.venv/Scripts/python.exe -m streamlit run app/frontend.py
```

产物位置：`generated/{task_id}/`（`spec.json`、`game_vN.html`、`assets/`、`qa/`、`manifest.json`），
前端：`http://localhost:8501`，游戏预览：`http://localhost:8080/{task_id}/game.html`。

## 七、结论

- **能被验证的部分**：需求→规格→编码→验证→修复→模拟→报告→交付，这条链在本机真实跑通，且失败会显式暴露而不是伪装成功。
- **不能被验证的部分**：合成玩家的"留存/付费"不构成市场结论；APK 只验证了可构建，没做真机兼容性测试；3D 与 iOS 只是接口预留。
- **这套东西的价值**：不是替代游戏开发者，而是把"值不值得投入"的判断成本压到分钟级，让策划的试错次数变多。
